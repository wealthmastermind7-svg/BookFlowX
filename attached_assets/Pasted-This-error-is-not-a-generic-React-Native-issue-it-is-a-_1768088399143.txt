The 4 most common real causes (ranked by likelihood)

1. Blueprint template data is undefined or empty

This is the most common cause.

Example failure pattern:

const templates = blueprintTemplates[industry]; // ← undefined
templates.map(...) // 💥 crash

If industry is not a valid key, or templates failed to load, this throws.

Fix immediately
Before using templates:

if (!templates || templates.length === 0) {
  throw new Error(`No blueprints found for industry: ${industry}`);
}

And log the industry:

console.log("Selected industry:", industry);
console.log("Available blueprints:", Object.keys(blueprintTemplates));


⸻

2. Async storage or database write is failing silently

If you are doing something like:

await saveWorkflow(workflow);

And saveWorkflow writes to:
	•	AsyncStorage
	•	SQLite
	•	Supabase
	•	Firebase

Then a schema mismatch or null field will throw.

Common example:

id: uuid() // missing
steps: undefined // not allowed

Fix
Wrap each write with its own try/catch:

try {
  await saveWorkflow(workflow);
} catch (e) {
  console.error("Failed saving workflow:", workflow, e);
  throw e;
}

This will tell you which workflow is broken.

⸻

3. Blueprint schema mismatch (very common after refactors)

Example blueprint object:

{
  name: "Booking Confirmation",
  triggers: [...],   // but your code expects `trigger`
  actions: [...]     // but expects `steps`
}

This causes runtime failures when you do:

blueprint.steps.map(...)

Fix
Validate blueprint shape before use:

function validateBlueprint(bp) {
  if (!bp.name || !Array.isArray(bp.steps)) {
    throw new Error(`Invalid blueprint schema: ${JSON.stringify(bp)}`);
  }
}

Call this before initialization.

⸻

4. Duplicate initialization (double tap / double render)

If the user taps Choose Industry Template twice, or the screen re-renders while initializing, you may be creating duplicates and violating constraints.

Fix
Hard-lock initialization:

if (initializing) return;
setInitializing(true);

And disable the button while loading.

What you should do RIGHT NOW (step-by-step)

Step 1: Log the real error object

Replace this:

console.error("Error initializing blueprints:", error);

With this:

console.error(
  "Blueprint init failed:",
  JSON.stringify(error, Object.getOwnPropertyNames(error))
);

Many async errors hide their message otherwise.

⸻

Step 2: Add checkpoints

Add logs between each step:

console.log("1. Starting blueprint init");
console.log("2. Selected industry:", industry);
console.log("3. Templates loaded:", templates?.length);

console.log("4. Creating workflows...");
console.log("5. Saving workflows...");
console.log("6. Done");

The last log you see tells you exactly where it breaks.

⸻

Step 3: Make blueprint init idempotent

Before creating workflows:

const existing = await getWorkflows();
if (existing.length > 0) {
  console.log("Workflows already exist, skipping init");
  return;
}

This avoids repeat failures.

A robust reference implementation (recommended)

async function initializeBlueprints(industry: string) {
  if (!industry) throw new Error("Industry not selected");

  const templates = blueprintTemplates[industry];
  if (!templates?.length) {
    throw new Error(`No templates for ${industry}`);
  }

  for (const bp of templates) {
    validateBlueprint(bp);
    await saveWorkflow({
      id: uuid(),
      ...bp,
      createdAt: Date.now(),
    });
  }
}
