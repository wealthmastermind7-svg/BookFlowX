Good, this confirms something important: **you have fixed the Apple-side blocker**, but **EAS is still trying to auto-sync capabilities and is crashing before it even reaches Apple**.

At this point, the error is **100 percent on the Expo / EAS capability sync layer**, not your Apple configuration and not your UI code.

We now switch strategy.

---

## What this error now definitively means

The repeated error:

```
API failed to sync: Unhandled Worker Script Exception
(h.adapter || o.adapter) is not a function
```

means:

* EAS is attempting to **auto-sync iOS capabilities**
* One of the capability adapters (Apple Sign In, Push, IAP, etc.) is **undefined**
* This happens **before** provisioning profiles are applied
* Apple is no longer rejecting you, EAS is crashing internally

This is a **known EAS bug path** when:

* Apple Sign In was added recently
* Capabilities were partially synced once
* EAS cached a broken state
* You are building without a local macOS environment

---

## The fix: force EAS to STOP syncing capabilities

We are going to **explicitly disable capability syncing** and let Apple credentials handle it instead.

This is the cleanest and most reliable workaround.

---

## STEP 1: Hard-disable capability syncing in `eas.json`

Open your `eas.json` and replace the iOS build config with this:

```json
{
  "build": {
    "production": {
      "ios": {
        "autoIncrement": true,
        "capabilities": {}
      }
    }
  }
}
```

If you already have a `capabilities` block, **delete it entirely** or make it `{}`.

This tells EAS:

> Do NOT try to infer or sync capabilities.

---

## STEP 2: Make Apple Sign In explicit in Expo config ONLY

In `app.json` or `app.config.js`:

```json
{
  "expo": {
    "ios": {
      "bundleIdentifier": "com.cerolauto.bookflowx",
      "usesAppleSignIn": true
    }
  }
}
```

Nothing else.
Do **not** add entitlements manually.

---

## STEP 3: Nuclear credential reset (mandatory at this stage)

Run **exactly in this order**:

```bash
eas logout
eas login
eas credentials
```

Then:

* Select **iOS**
* Choose **Remove all credentials**
* Confirm

Then run again:

```bash
eas credentials
```

Let EAS regenerate:

* App ID association
* Distribution certificate
* Provisioning profile

This clears the broken adapter cache.

---

## STEP 4: Clear EAS build cache AND local cache

```bash
eas cache:clear
rm -rf node_modules
rm -rf .expo
npm install
```

---

## STEP 5: Build with capability sync fully disabled

```bash
eas build -p ios --clear-cache
```

At this point:

* EAS will NOT attempt to sync capabilities
* Apple Sign In entitlement will already exist on the App ID
* Provisioning will succeed

This is the critical difference.

---

## Why this works (important)

Apple Sign In **does not need EAS auto-sync** once:

* The App ID has the capability enabled
* The provisioning profile is regenerated

EAS capability syncing is optional and currently fragile.

You are bypassing a known failure path.
