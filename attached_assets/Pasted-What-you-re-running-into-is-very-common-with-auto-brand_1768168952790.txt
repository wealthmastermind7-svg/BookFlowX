What you’re running into is very common with “auto brand color extraction”, and the issue is not that your logic is wrong, it’s that modern websites do not expose brand colors in a clean, crawlable way.

I’ll break this into three parts:
	1.	Why it’s not working (the real reasons)
	2.	What will never work reliably (important)
	3.	How to fix it so it works in production

⸻

1. Why your current approach fails (even if implemented correctly)

You said you are:

fetching the website, scanning HTML and CSS for colors used in buttons, headers, logos, branding classes, and picking the most frequent colors

That sounds right, but modern sites like mintwash.com break this in several ways.

A. Most brand colors are NOT in static HTML or CSS

Common patterns you’ll see:
	•	Tailwind CSS with dynamic classes
	•	CSS variables defined in JS at runtime
	•	Inline styles injected after hydration
	•	SVG logos with embedded gradients
	•	Canvas-based or image-based branding

Example:

--brand-primary: hsl(var(--primary))

Your crawler sees no real color.

⸻

B. “Most frequent color” is almost always wrong

Frequency-based selection usually returns:
	•	White #ffffff
	•	Black #000000
	•	Gray backgrounds
	•	Border colors
	•	Neutral text colors

Brand colors are often:
	•	Used sparingly
	•	Only on CTAs
	•	Present in SVGs or images
	•	Applied conditionally (hover, focus)

So your algorithm is doing what you asked, but that’s not what you want.

⸻

C. Logos are usually images (and not parseable via CSS)

Most sites:
	•	Use PNG / SVG logos
	•	With gradients or multiple tones
	•	Loaded via <img> or background-image

Your HTML/CSS scan never sees the brand color, only the image URL.

⸻

D. Modern sites block or alter crawlers

Some sites:
	•	Serve different CSS to bots
	•	Delay loading styles
	•	Rely on client-side rendering

If you’re not running a headless browser, you’re not seeing the final DOM.

⸻

2. What will never work reliably (important reality check)

❌ Pure HTML + CSS scraping
❌ Frequency-based color picking
❌ Expecting brand colors to appear in CSS
❌ Expecting logos to expose colors
❌ Expecting Tailwind sites to reveal tokens

If you keep iterating this approach, you’ll keep getting “almost works” results.

⸻

3. How to fix this properly (production-grade solution)

The fix is multi-layered, not a single algorithm.

✅ Solution Architecture (What actually works)

You need a 3-pass color extraction system with confidence scoring.

⸻

PASS 1: CTA-FIRST COLOR DETECTION (Highest accuracy)

Instead of scanning everything, target intent-heavy elements:

Specifically scan:
	•	Primary buttons (button, [role="button"])
	•	Links with large font-weight
	•	Submit buttons
	•	Sticky CTAs
	•	Pricing buttons

Then extract:
	•	background-color
	•	border-color
	•	box-shadow
	•	hover state color

This alone captures brand colors on 70%+ of sites.

Brand colors live where conversion happens.

⸻

PASS 2: LOGO IMAGE COLOR SAMPLING (Critical)

For logos:
	1.	Detect <img> or <svg> that matches:
	•	alt contains brand name
	•	class contains logo
	•	header placement
	2.	If image:
	•	Download image
	•	Run k-means color clustering (k=3–5)
	•	Ignore whites, blacks, grays
	•	Pick highest saturation color

This solves the “mintwash.com” problem specifically.

⸻

PASS 3: FALLBACK + SANITY FILTERING

If no strong signal:
	•	Exclude:
	•	#fff, #000
	•	Colors with saturation < 15%
	•	Prefer:
	•	Saturation > 40%
	•	Hue variance
	•	Bias toward:
	•	Green / Blue / Brand-typical hues if domain suggests it

⸻

Confidence scoring (THIS IS KEY)

Each detected color should have:

{
  color: "#2ecc71",
  source: "primary_button",
  confidence: 0.82
}

Then:
	•	Pick top 1–2 colors
	•	Show user:
“We detected these brand colors from your website. Adjust if needed.”

This turns a technical limitation into a premium UX feature.

⸻

UX FIX (Important)

Instead of saying:

“Match Website”

Change copy to:

“Detect brand colors (beta)”

And show:
	•	Detected colors
	•	Source (“From CTA button”, “From logo”)
	•	Editable swatches

This massively reduces user frustration.

⸻

Why mintwash.com is a perfect test case

Mintwash-style sites usually:
	•	Use Tailwind
	•	Use SVG logos
	•	Use subtle gradients
	•	Use limited CSS tokens

Which means:

If it works on mintwash.com, it will work almost everywhere.

TL;DR – Why it’s broken and how to fix it

Why it’s not working
	•	Brand colors aren’t in static CSS
	•	Frequency-based logic selects neutrals
	•	Logos hide color info in images

How to fix it
	•	Prioritize CTA elements
	•	Extract colors from logo images
	•	Use confidence-based multi-pass detection
	•	Make it user-adjustable
